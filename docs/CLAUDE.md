# 一迈一记（SlowNote） AI 协作规范

> 项目标识：`slownote`｜版本：1.4｜更新日期：2026-11-11

## 1. 协作目标

AI 参与一迈一记（SlowNote）的分析、实现与验证时，必须以已确认的 PRD 和本目录规范为依据。产品定位：记录宝宝成长的微信小程序，记录管理与小迈 AI 问答、定时报告是核心能力。底部「小迈」页提供即时问答入口与按记录类别查看趋势的二级页；喂养、成长、里程碑、辅食、便便、日记和自定义记录提供数据来源。定时报告按「数据类型（7 类，与常见问题同一套枚举）+ 数据范围（跟随频率/今天/近 3 天/近 7 天/近 30 天，与频率解耦）+ 频率」配置，生成结果写入站内报告，由「我的 → 历史报告」集中查看、标记已读与左滑删除；底栏不做未读数字角标。产品可继续扩展宝宝生活记录。用户登录后可使用全部功能；登录身份用于数据隔离。技术栈：原生微信小程序（WXML/WXSS/JS）+ 微信云开发（云函数、云数据库、云存储）。

## 2. 工作边界

- 先说明理解、影响范围与验证方式，再修改文件。
- 不编造接口、数据结构、权限、业务状态或验收结论；信息不足时写 `[待补充：具体缺失信息]` 并请求确认。
- 不擅自扩大任务、部署上线、写入生产数据或执行不可逆操作。
- 保留用户已有改动；覆盖、删除、迁移前明确目标与影响。
- 只在 `miniprogram/` 放置前端实现。
- 只在 `cloudfunctions/` 放置后端实现，接口与数据责任边界必须显式记录。

## 3. 事实来源优先级

1. 用户本轮明确指令。
2. `docs/prd/slownote-prd.md`。
3. `docs/rules/` 下与任务相关的规范。
4. `docs/database-design.md` 中已确认的数据模型与约束。

来源冲突时暂停实现并列出冲突，不自行选择对业务影响更大的解释。

## 4. 实施闭环

1. 读取相关需求与规则，列出明确验收标准。
2. 检查现有实现和调用链，限制改动范围。
3. 小步实现；新增行为须有可重复验证。
4. 执行与风险相称的测试、静态检查和构建检查。
   接口或返回数据有变更时，须用源码检索确认页面实际发起了对应调用并消费新字段，交付附调用点证据；仅完成云函数实现不能判定功能完成。
5. 复核路径、错误处理、安全、可访问性和端侧适配。
6. 返回实际变更、验证证据、未解决项与下一步。

## 5. 质量红线

- 禁止硬编码密钥、令牌、个人信息与环境地址。
- 禁止吞掉异常、伪造成功结果或删除失败证据。
- 禁止为通过检查而弱化测试、类型或权限边界。
- 公共能力优先复用；抽象必须来自真实重复，不预建未确认能力。
- 用户身份字段统一为 `openid`；业务对象关联字段默认 `entity_id`，仅在需求明确适用时使用。

## 6. 端侧约束

- 微信小程序：遵守分包、隐私授权、API 兼容、安全区与真机验证要求。
