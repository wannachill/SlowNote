# 一迈一记 SlowNote 产品需求与验收
> 版本 1.11｜2026-11-12｜实现范围以本文和工程为准；云端部署、设备验收另见部署清单。

## 1. 定位与边界
记录宝宝一生数据的成长笔记。面向父母与照护者，夜间单手记录优先。原生微信小程序 + 云开发；用户登录后可使用全部功能，登录身份用于数据隔离。无社区、广告或电商。
已实现：首页/小迈/我的三导航、日期首页、6 套渐变主题色（治愈蓝/樱粉/暖橙/薄荷绿/紫色/深色）、多宝宝档案、自定义记录、首页全宽时间轴记录卡与汇总标签多选筛选。小迈页提供不预填问题的通用问答入口与六类概况卡；只展示选定范围内有记录的类别，未记录类别不显示；整个范围均无记录时隐藏概况卡片区并显示首次登记引导。统计详情页提供指标切换标签、可横向滑动的趋势图与选中日期当天明细。横滑仅移动趋势视口，当天明细保持选中日期不变；趋势画布固定为视口宽，横滑由透明占位层驱动。小迈对话支持记录快照问答与图片/语音输入，定时报告支持按数据类型与数据范围配置、每天/每周/每月生成并推送，历史报告集中查看详情与左滑删除。首页问答入口已移除；撒花保留用于成长里程碑达成。网络状态横幅、底栏状态、图表绘制与日记列表反馈按各页面实现；底栏不再展示未读数字角标。独立家庭管理、药品/护理日常记录、月报页面/函数与智能提醒（含其云函数、定时器与信息推送中转页）已下线；家庭成员数据隔离兼容和 expense 历史集合保留。首页与小迈切换 Tab 时复用 60 秒内的读取缓存并静默校验，记录变更、删除卡片、切换宝宝后立即失效，不重复请求云端。

## 2. 产品结构

| 入口 | 当前实现 |
|---|---|
| 首页 | 宝宝昵称/月龄、周历与可展开月历、日期切换、全宽单列当日时间轴卡、当日汇总标签多选筛选、圆形记录 FAB 与六类登记面板；已登记卡片长按可整理和删除当天该类别记录。首页不放「问小迈」按钮，问答入口位于底部「小迈」Tab |
| 小迈（底部 Tab） | 页面标题「小迈」左对齐、提示语「问一句，一眼看懂宝宝的成长。」在标题下方，顶部标题区高度与「我的」「首页」一致；日期范围筛选（今日/本周/本月/全部）位于「宝宝概况」标题行右侧、不占用顶部标题区；通用搜索框式入口进入空白对话，自由输入问题。只展示选定范围内有记录的类别卡（成长/喂养/辅食/便便/日记/自定义）；有记录卡片显示指标与适用的环比信息并可进入统计详情。成长/喂养为多项指标卡，统一三列：标签｜数值+单位｜环比变化，变化不重复单位；其余为单指标卡。整个范围均无记录时隐藏「宝宝概况」区，显示去首页登记的引导。概况卡带 type 与 range 进入统计详情，详情页明细仅展示该类型记录 |
| 统计详情 | 普通二级页，标题为「{类型}趋势」；统计范围由小迈概况卡进入时传入，页内不另设范围筛选；多指标时显示灰白胶囊指标切换，主体为折线趋势图与选中日期的该类型明细时间线卡片（按进入时的类型过滤，不含其它类型）；明细仅在点选日期时切换；横滑只用于浏览历史趋势，不改变选中日期、不触发后台查询；统计范围由概况卡传入。纵坐标刻度位于右侧紧凑固定栏，宽度跟随刻度文字；左侧绘图区独立横滑并在纵轴栏前结束。横轴可左右滑动查看更多日期、点选日期以加粗实心节点强调，不画竖向高亮虚线；不显示日历热力图 |
| 发育里程碑 | 独立二级页（首页/成长页入口）；按 1~36 月龄连续展示当前月龄里程碑清单，每龄均已内置最关键的发育里程碑（68 项，五维度：大运动/精细动作/语言/社交/其他），缺失月龄由云函数幂等补齐且不覆盖用户自定义与已打卡记录；支持增删改与同月龄内排序、点卡片或圆圈勾选直接打卡/取消并撒花、左滑编辑/删除、长按拖动排序、右下 FAB 新增 |
| 我的 | 微信身份登录/本地退出，入口自上而下固定为：主题设置、小迈设置、定时报告、历史报告。宝宝信息支持多档案添加、切换、编辑、删除与头像，卡片左滑编辑/删除、点击切换当前宝宝；小迈设置包含深度思考入口显示、风格/图片/报告提示词和常见问题管理 |
| 小迈对话 | 通用问答 + 记录数据问答；输入支持图片与语音。当前个人主体不可用 WechatSI，语音使用 RecorderManager 录音，松开后经 asrProxy 一次性转写；主体变更为非个人后可加回声明恢复实时预览。无单独数据范围按钮，按提问文字识别今天/昨天/周/月/近期时段并附加对应范围的服务端渲染记录明细与计数概览；常见问题支持按问题配置数据类型（喂养、便便排尿、辅食、成长、成长日记、里程碑、自定义，可多选或一键全选），推荐问题只附带所选类别的具体登记明细，自由提问不带类别时仍为全量；空选不取数、不附带。明细只含白名单日期、事项/正文/数值，按条目与总长度截断并注明未展开数量；用户主动确认发送后才随问题发给第三方 AI。小迈主页面入口不带 seed，打开空白输入；用户主动选择常见问题等快捷问题时，seed 仅预填问题，由用户确认发送。深度思考入口显示由 ai_settings 配置，用户开关偏好本地保存；回答按 Markdown 渲染，历史对话可恢复。常见问题由 ai-settings 页面管理，对话欢迎态以气泡显示。对话历史写入 ai_sessions；云函数自动注入宝宝性别与月龄上下文，不含昵称/生日原文 |
| 定时报告 | 表单分三段：**数据类型**（多选，与常见问题同一套 7 类：喂养、便便排尿、辅食、成长、成长日记、里程碑、自定义，feeding/excretion/solid 同源于喂养记录但可分别选择；选择器与「新增常见问题」一致：标题行 + 全选/取消全选 + 流式 pill 标签）、**数据范围**（跟随频率/今天/近 3 天/近 7 天/近 30 天，与频率解耦：频率决定多久出一份，范围决定这份看多久）、**频率与时间**（每天/每周/每月；月度任务固定分析上月整月，范围选择隐藏并回落到跟随频率），另设「报告标题」（≤20 字，用作推送摘要）。范围大于出报告间隔时相邻报告会有重叠，小于间隔时会漏掉区间外记录，表单底部实时说明该后果。顶部为蓝色「页面用途说明」提示卡（`--color-accent-soft` 底 + 左侧主题色竖条 + 圆角与阴影，与「常见问题」页一致，且与下方卡片等宽），说明报告先存站内、可按卡片单独开启微信推送；**已移除全局「开启通知」按钮**，站内入口改由「我的 → 历史报告」进入。「报告任务」区由「＋ 添加」按钮弹出表单、不常驻表单；任务卡片左滑展开编辑与删除，正面保留原生 switch **单独控制该任务的微信通知**（`notify`，乐观更新、不弹提示、不刷新列表），卡片只展示报告标题、频率与时间、异常时才显示状态标签，不展示数据类型、北京时间与数据范围；编辑走 aiTasks 的 action:'update'，复用新增校验、重算 next_run_at 并清空租约。报告正文写入 ai_notifications；订阅消息字段为 thing1 报告类型、time2 生成时间、thing3 报告结果（取任务「报告标题」，未配置则不展示该字段），点击跳回历史报告 |
| 历史报告 | 独立二级页，标题「历史报告」，顶部起止日期选择器（默认本月，北京时间、含起止当天）。卡片两行布局：首行报告标题（取自任务 `report_title`，旧记录兜底「小迈定时报告」）与右侧发送时间；次行左侧微信渠道短标签（`微信已送达` / `站内信` / `微信未送达`，彩色 `status-tag`）、右侧实心主题色「未读」标签。**不展示正文预览、数据类型与「站内通知」全称**；点击卡片弹出详情面板查看完整正文并自动标记已读（详情区时间与状态标签垂直居中对齐）。卡片左滑露出「删除」（按钮宽度与「常见问题」单个动作等宽，即 `calc(var(--swipe-action-width) / 2)`），删除需二次确认，成功后移除并刷新列表。未读数不做底栏角标提示。云端 `aiNotifications` 提供 `list`（`startDate`/`endDate` 日期筛选 + `offset` 分页，每页 20 条，返回 `total`/`hasMore`）/`read`/`remove`，按 openid 校验归属并以 clientRequestId 幂等 |

首页、小迈、我的为唯一底部三导航，采用自定义 tabBar（SVG mask 线性图标，选中强调色）。记录入口为 FAB → 类目，最多两次点击到登记页。选中日期传入目标表单。小迈主页面顶部提供搜索框式问答入口，不在首页重复提供「问小迈」入口。全部页面使用自定义导航栏：Tab 页无顶部标题、页内大标题；子页面统一 .sub-nav 大标题 + 返回按钮。

## 3. 类目与兼容
| 面板类目 | 登记页 | 数据行为 |
|---|---|---|
| 喂养 | 独立喂奶页 pages/feeding（页内可切亲喂/瓶喂/配方奶；亲喂记时长，其他方式记奶量 ml） | feeding_records.type=feed，payload.mode=breast/bottle/formula；mixed 仅历史兼容 |
| 辅食 | 独立辅食页 pages/solid（名称/备注） | type=solid |
| 便便 | 独立便便页 pages/excretion（页内可切大便/小便） | type=excretion，payload.kind=stool/urine；大便=次数/选填性状，小便=次数 |
| 身高体重 | growth | growth_records |
| 育儿日记 | diary | diary_records |
| 自定义 | custom-record | category=custom，名称/可选数值/单位/备注 |

成长页与首页保留「发育里程碑」入口（pages/milestone，milestone_records + milestone_defs）；里程碑页按 1~36 月龄连续展示，支持增删改与同月龄内排序（内置项可隐藏、自定义项可删除），点卡片或圆圈勾选直接打卡/取消并撒花，左滑编辑/删除、长按拖动排序、右下 FAB 新增。药品/护理日常记录页面、接口与集合已从当前产品移除；发育里程碑是独立保留的记录功能。自定义记录的单位为自由输入，前端最多 6 字；服务端字段校验上限为 8 字。花销已停止新增，expense_records 历史数据保留。类目名称：身高体重=成长、育儿日记=日记、换尿布=便便；类目顺序为喂养/辅食/便便/成长/日记/自定义。

旧 feed/solid/excretion、mode=mixed、历史云图片和原 API 返回结构继续支持。没有把既有记录重命名或迁移。新 feeding/diary 记录增加 record_date；旧记录按 created_at 的北京时间归日。记录写入带 client_request_id；超时重试复用请求标识。

## 4. 日期与统计口径
- 首页默认北京时间今天；周从周日开始，可前后切周、展开整月、选日、回到今天。未来日期可查看，写入仅允许今天及过去。
- 当日卡片按各喂养细类、成长、日记、自定义、里程碑展示；无数据给出空态提示（“这一天，还没有记录”，记录入口为右下 FAB），失败给出重试，未登录给出登录入口。
- 首页卡片整理：长按卡片进入整理态；轻按仍打开原登记内容页。整理态仅保留卡片轻微 ±2° 抖动和右上角删除入口，不改变时间线位置。点击删除后先二次确认，再删除当前选中日期、当前宝宝、当前类别的全部登记，约 200ms 缩放淡出后刷新首页/统计。
- 今日为北京时间自然日，本周=周日至下一周日前，本月=自然月；全部读取可见范围。小迈主页面范围为今日/本周/本月/全部，详情页沿用相同范围。trend 响应含逐日 `series`、精简 `totals` 与周/月 `prevTotals`；今日/全部无环比。trend 的 `dates.start` 回填最早记录日期（无记录时为空）。服务端按当前宝宝及个人/家庭 scope 查询。
- 奶量只合计实际录入的 ml；亲喂分钟不折算 ml；成长指标分别取范围内最后一个有效值。趋势为分别缩放的记录曲线，不是百分位、诊断或医学参考范围。
- 聚合按集合分页读取，单集合超过 10000 条返回 413 提示缩小范围，不返回冒充完整的截断统计。

## 5. 宝宝与主题
支持多宝宝档案：babies 集合多记录，我的 → 宝宝信息页可添加/切换/编辑/删除/上传头像；业务记录按 baby_id 归属，切换当前宝宝后各功能按当前宝宝记录与查看（旧数据无 baby_id 时兜底兼容）。生日选填，使用原生 picker mode=date（上限今天）；性别为暂不填写/男/女；头像默认按性别取内置（男宝深蓝短发/女宝黑双发髻），可上传照片。
6 套渐变主题（治愈蓝 / 樱粉 / 暖橙 / 薄荷绿 / 紫色 / 深色）：每套沿用同一套柔和弥散 radial-gradient 色斑质感，仅色相不同。默认治愈蓝为白底叠加低透明度蓝 #598BFD / 薄荷绿 #9AD4CB / 青 #35B3C9 弥散背景、强调 #5B9BD5、深蓝 #2E6DA6；樱粉 / 暖橙 / 薄荷绿 / 紫色为各自浅色系渐变与强调墨色；深色主题复用压暗同色相背景（基色 #101923），卡片 #1D2A37、表单 #243343。原浅蓝 #EDF4FB / 深 #141D27 保留作系统背景兜底。深色作为独立主题色存在，不再区分“皮肤与背景色”的明暗模式。
主题设置提供 6 种渐变主题色，以圆点选择器切换，无浅色/深色模式开关、不提供跟随系统选项。偏好立即写本地 storage（{color}），登录后同步 users.theme_pref（{color}）；旧版本地或云端仅含 mode（light/dark/system）的值在读取/写入时按 color 归一（dark→dark、light/system→blue）并写回，此后不随系统外观变化。弱网提示仅本机生效并保留待同步标志。主题仅改变配色与渐变，不改变布局。

## 6. 小迈与推送
- aiChat 使用服务端 HTTPS OpenAI 兼容 chat/completions；模型、地址和密钥只通过环境变量配置，不绑定服务商。
- 对话自动注入当前宝宝性别与月龄上下文（不含昵称/生日原文），不自动附带记录。`digest.detectRange()` 按提问识别今天/昨天/本周/上周/本月/上月/全部时间及近期天/月；滚动天/月长度上限为 90 天。用户确认发送后，问答只附带服务端按七类白名单过滤并渲染的登记明细；自由提问未指定类别时兼容全量，常见问题按配置类别取数，空选不取数。日记正文每条最多 120 字，备注最多 60 字，每类最多 20 条，超过长度预算明确标注未展开数量。发给第三方 AI 的明细经 `redact()` 脱敏，不包含 openid、家庭/宝宝标识、昵称、生日原文、created_at 原文、请求 ID 或云文件 ID；不要输入私人住址等敏感文本。
- 每用户每分钟最多四次问答。对话在页面内即时可用，并异步保存到云集合 ai_sessions（openid 隔离、幂等 upsert、图片仅存 fileID、保存失败静默降级不阻断）；离开后可经历史对话恢复。
- AI 任务需要用户明确同意。daily 分析当日，weekly 分析最近七日，monthly 于每月 1 日分析上一个完整自然月。第三方 AI 仅在任务已获同意且任务启用时收到所选类别的记录明细白名单与计数概览；包括成长日记正文、里程碑事项名、辅食/自定义备注。明细经脱敏，不发送 openid、family_id、baby_id、记录 `_id`、client_request_id、created_at 原文、宝宝昵称/生日原文或图片/音频 fileID。
- `ai_settings` 由 aiSettings 云函数读写，文档为 `_id=hash(openid)`，持久化 `openid`、`showThinking`、`prompts.style/vision/report`、`updated_at`。固定安全规则由服务端代码组合返回，不存入用户文档；提示词按对话/图片/定时报告场景组合。常见问题由 `ai-settings` 页面管理并存于端侧存储，不属于 `ai_settings` 字段。
- aiReport 每五分钟轮询，批次最多十任务、并发二；任务租约与确定性运行/通知 ID 防止重复触发。后台按任务所有权与同意状态验证。
- 先保存 ai_notifications，再尝试一次微信订阅消息。未配置模板封装返回 501，用户在站内可见；未订阅/次数耗尽/发送失败不显示为成功推送。时间按五分钟轮询可能延迟，队列积压会继续顺延。
- 未配置模型返回友好说明，不伪造分析。始终标注“AI 生成，仅供参考”，异常健康情况引导就医，不能替代专业诊疗。

## 7. 登录与隐私

### 7.1 登录方式：云开发静默识别（无授权弹窗）
- 身份来源：`miniprogram/app.js` 在 `onLaunch` 自动调用 `wx.cloud.callFunction({ name: 'login' })`；`cloudfunctions/login/index.js` 用 `cloud.getWXContext().OPENID` 取得微信在请求层注入的可信登录态。云开发天然携带身份，无需 `wx.login`、code2session、自建 token 或续期，也不存在登录态过期重登链路；`wx.cloud.init` 设 `traceUser: false`。
- 自动建档：首次调用按 openid 查 `users`，查不到即自动写入（`openid`、`nickname: ''`、`created_at`、`last_login_at`），此后只更新 `last_login_at`。**无需为任何用户预先开通账号**，打开小程序即直接登录可用；「我的 → 微信登录」按钮只是弱网或未部署后的重试连接，不是注册入口。前端只把 `openid`、空 `nickname` 与 `loggedIn` 写入 `globalData`。
- 不获取的信息：**微信号、微信昵称、头像、手机号、性别、地区等任何个人资料**。微信平台不提供「微信号」查询能力；`scope.userInfo` 已在小程序端回收、`wx.getUserProfile` 新版返回占位信息，官方现行方案「头像昵称填写能力」（`open-type="chooseAvatar"` + `input type="nickname"`）属用户主动填写而非读取微信资料；本项目个人主体亦不可用需微信认证的手机号组件。因此**登录前没有用户资料授权弹窗**；`users.nickname` 建档后无写入口，恒为空字符串，「我的」页展示的是 `babies` 表的宝宝昵称而非用户微信昵称。
- 唯一的授权弹窗是订阅消息一次性授权：`miniprogram/pages/ai-tasks/index.js` 在用户手动打开某张报告任务卡片的「微信通知」开关时调用 `wx.requestSubscribeMessage`，仅用于定时报告微信推送，与登录无关，额度可耗尽、失败不影响站内报告。
- 退出为本机退出：清空内存身份与缓存、写 `slownote_signed_out` 并阻止自动再次登录，不删除云记录，也不撤销微信平台身份；重新登录可恢复。

### 7.2 数据隔离
- 每个云函数经 `cloudfunctions/_shared/runtime.js` 的 `identity()` 从可信上下文重新取 `openid` 并校验 `users` 存在，**不信任客户端传入的用户标识**；`access()` 按 `{openid}` 构造查询 scope。记录集合按 openid 归属，云存储路径（`audio/{openid}/`、`ai-chat/{openid}/`、`diary/{openid}/`）同样按 openid 分片且服务端校验 fileID 归属；`ai_settings`、`ai_rate_limits`、`mutation_receipts` 与宝宝档案以 `hash(openid:...)` 为确定性文档 ID，天然隔离。问答只在用户主动确认附带、定时报告只在已同意任务运行时，向第三方 AI 发送所选类别的白名单明细；日记正文、里程碑事项名、辅食/自定义备注可能包含在内，发送前经脱敏。身份、生日原文、请求 ID、原始时间戳和云文件 ID不外发。
- 隔离边界：不同微信号 → 不同 openid → 数据互不可见；同一微信号换设备或重装小程序 → openid 不变 → 数据自动恢复；更换 AppID 或云环境 → openid 变化、数据不互通；`unionid` 未落库，跨小程序 / 公众号的账号打通未实现。
- **历史例外**：`family_members` 命中时 `access()` 把 scope 切为 `{family_id}`，同家庭成员共享数据。家庭管理产品入口已下线但历史数据保留，故准确表述为「按可信 openid 或历史家庭 scope 隔离」；新用户无该记录即纯个人隔离。
- 所有登录用户可使用全部功能，登录门禁只负责引导，不承担数据权限判断。主题可离线修改，记录不宣称具有离线队列。

### 7.3 隔离生效的控制台前置（登录与上线阻塞）
代码只提供隔离能力，**是否真正生效取决于云开发控制台配置**；执行与勾选见 `docs/release-checklist.md` 阶段 1、阶段 3。
- **#06 创建 16 个集合（含 `users`）**：`login` 先执行 `users.where({ openid }).get()`，集合不存在会直接报错、自动建档失效、全员停在未登录态；另需 #04 确认 AppID / 环境 ID 一致、#16 部署 `login` 云函数（未部署时前端静默保持未登录态）。
- **#07 设置客户端权限**：除 `ai_sessions` 外全部「所有用户不可读写」，`ai_sessions` 放行「仅本人读写本人记录」（`doc.openid == auth.openid`）。未配置前客户端可绕过云函数直连数据库，理论上有越权读取风险。
- **#08 `users.openid` 唯一索引**：避免同一 openid 重复建档。
- 真机验收建议随 #27 / #33 一并执行：两个不同微信号各记一条数据互不可见；同账号退出重登、换设备后数据可恢复。

### 7.4 合规待办
除 `ai_sessions` 由小程序端按安全规则写入外，集合仅允许云函数访问；服务端校验登录身份、家庭 / 宝宝数据范围及对象归属。隐私协议 / 用户隐私保护指引需覆盖录音用于语音识别、宝宝记录与照片等实际收集范围，并明确「成长日记正文、里程碑事项、辅食/自定义备注会在用户主动附带问答或已同意的定时报告中发送给第三方 AI 服务商」（清单 #15）。AI 服务商、隐私政策、数据保留与删除责任人：[待补充：上线前确认]。
