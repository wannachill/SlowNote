# 一迈一记（SlowNote） 代码风格规范

## 1. 优先级

项目已有格式化器、静态检查器和语言官方约定优先；本文补充跨技术栈一致规则。技术栈：原生微信小程序（WXML/WXSS/JS）+ 微信云开发（云函数、云数据库、云存储）。

## 2. 命名

- 名称表达业务含义，避免无上下文缩写、拼音和 `temp/new/final2`。
- 类型/组件、函数、变量、常量和文件名遵循所用语言及框架约定。
- 布尔值使用可判断前缀；集合使用复数；单位写入名称，如 `timeoutMs`。

## 3. 结构

- 函数单一职责；复杂条件提炼为有意义的判断。
- 依赖从边界注入，避免隐藏全局状态和模块加载副作用。
- 只抽象真实重复；公共模块必须有清晰输入、输出和错误约定。
- 注释解释原因、约束和取舍，不复述代码。

## 4. 类型与错误

- 边界输入先校验再转换；核心逻辑避免无约束动态值。
- 禁止空捕获、仅打印后继续、返回伪成功或暴露内部异常。
- 错误保留原因链和可追踪上下文，但不包含密钥或个人信息。

## 5. 异步与资源

- 异步调用明确超时、取消、重试和竞态处理。
- 文件、连接、订阅和定时器在所有路径释放。
- 重试只用于可重试错误，必须有限次且考虑幂等。

## 6. 测试

- 新行为和缺陷修复具备可重复测试；测试名称描述行为与条件。
- 优先验证公开行为，避免把实现细节或 mock 调用次数当作目标。
- 覆盖正常、边界、权限、失败和并发/重复操作（适用时）。

## 7. 提交前检查

- [ ] 格式、静态检查、类型检查、测试和构建通过。
- [ ] 无调试代码、未使用依赖、硬编码秘密和虚假占位值。
- [ ] 文档与行为同步；人工未决项保持 `[待补充：说明]` 格式。
