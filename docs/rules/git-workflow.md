# 一迈一记（SlowNote） Git 工作流

> 主分支：`main`｜开发分支：`develop`

## 1. 分支

- `main`：始终保持可发布，只通过评审和质量门禁合入。
- `develop`：用于团队约定的集成验证；若项目采用主干开发，可在评审后停用。
- 工作分支使用 `feature/`、`fix/`、`docs/`、`refactor/` 加短横线描述。
- 禁止直接向受保护分支强推、重写共享历史或提交无关大改。

## 2. 提交

格式：`type(scope): summary`

允许类型：`feat`、`fix`、`docs`、`refactor`、`test`、`build`、`ci`、`chore`、`revert`。

- 一次提交表达一个可解释变更，提交前通过相关检查。
- 不提交密钥、个人配置、构建产物或与任务无关的格式化噪声。
- 破坏性变更在正文说明迁移、兼容与回滚方式。

## 3. 合并请求

必须包含：目的、范围、关联需求、风险、验证证据、截图/录屏（界面变更）、迁移与回滚（适用时）。评审意见处理后重新验证受影响范围。

## 4. 发布

- 版本、变更日志和制品可追溯到提交。
- 数据或配置迁移先演练并准备回滚。
- 紧急修复仍需最小评审、自动检查和事后复盘。

## 5. 禁止项

- 禁止提交 `.env`、私钥、令牌和个人 `project.private.config.json` 内容。
- 禁止用跳过钩子、删除测试或降低规则掩盖失败。
- 禁止未经协商删除远程分支、标签或重写他人提交。
