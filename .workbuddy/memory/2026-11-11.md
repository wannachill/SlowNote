## 修复：单任务微信通知开关「无法开启生效」
- 用户实测卡片「微信通知」开关点不动/开不了。三处根因：
  1. **云端未重新部署**：`setNotify` 是上一轮新增的云端动作，用户上一轮"重新部署"在那之前完成，故云端没有 `setNotify` → 调用 400/UNKNOWN_ACTION → 开关存不住。这是主因。
  2. **手势被祖先拦截**：`task-actions` 上的 `catchtouchstart="noop"` 会阻断原生 `<switch>` 的点击（原生组件被祖先 catch 拦截的经典坑）。改为在 `switch` 自身加 `data-no-swipe` + `catchtouchmove="noop"`，去掉祖先 catch。
  3. **授权回退设计**：旧逻辑未点"允许"或开发者工具里授权没回 `accept` 就 `load()` 把开关回退成关，显得"开不了"。改为开关状态即偏好、立即乐观落库并保持开启；`wx.requestSubscribeMessage` 只决定能否真推微信，授权失败/未授权不再回退开关（报告仍先存站内）。
- 改动：`ai-tasks/index.wxml`（task-actions 去 catchtouchstart、switch 加 data-no-swipe+catchtouchmove）、`ai-tasks/index.js`（onNotifyChange 乐观更新 + _setNotify 先 setData 再 call）。测试同步文案断言（slownote.test.cjs：开关守卫提示「报告先存站内」、接受授权提示「已开启，报告将推送到微信」、手势防护断言 catchtouchmove+doesNotMatch catchtouchstart）。全量 282/282 通过，check-project 仍 5 个历史基线。
- 交付结论：代码已健壮化；**用户必须再重新部署一次 aiTasks（含 setNotify）+ aiReport** 才能真生效——这是"开不了"的实际修复点。

- 数据类型选择对齐常见问题（ai-tasks 添加/编辑面板）：用户要求与「新增常见问题」页一致。原 ai-tasks 数据类型是「数据类型（可多选）」+ 3 列网格按钮；常见问题为「数据类型」标题行 + 右侧「全选/取消全选」链接 + 流式 pill chips + 选中态。改造 `ai-tasks/index.wxml`：数据类型区改为 `task-category-heading`（label「数据类型」+ `text-action task-all-action` 切换「全选/取消全选」）+ `task-category-grid`（chips 复用 `type-btn`，去「（可多选）」字样，与常见问题视觉同构）；`ai-tasks/index.js` 新增 `allSelected` 数据与 `toggleAllCategories`/`syncAllSelected`（selectCategory、resetForm、startEdit 同步联动）；`ai-tasks/index.wxss` 新增 `task-category-heading/task-all-action/task-category-grid/.task-category-grid .type-btn(.active)`，样式 token 完全对齐 `question-category-*`（pill 圆角、accent-soft 选中、去 control-height 继承以匹配常见问题 chip 高度），并删除旧的 `.task-categories .type-btn` 三列网格规则（`.task-categories` 基础与 `.range-chips` 单选仍保留给数据范围）。
- 测试：feature-retirement.test.cjs / report-scope.test.cjs 旧「数据类型（可多选）」断言改「数据类型」+ 新增 `toggleAllCategories`/`task-category-grid`/`task-all-action` 断言；slownote.test.cjs 旧 `class="task-categories"` 改 `class="task-category-grid"`，并新增「数据类型全选/取消全选与 allSelected 联动」用例。另修复 3 个与本次无关的既有 stale 断言（report-history 的 status-unread 用 `--color-accent-ink`、milestone 的 record-fab 用 `--color-action` 与 done-check transition 用 `--motion-quick`）。
