关键结论（后续复用）：

- tests 只断言 tab wxss 的 padding 与 min-height（interaction-motion.test.cjs:115-116），删胶囊不会破测试

## 多宝宝支持度审查（14:51，只审不改）

结论：数据层 + 云函数层支持多宝宝，UI 层有硬伤 → 当前实际只能有 1 个宝宝。

支持的部分：
- `babies` 集合多文档；`babyProfile` 的 `listBabies`（limit 50）、`save`（带 babyId=更新 / 不带=按 hash(openid:clientId) 新建）、`delete`（按 babyId + scope 校验）
- `app.globalData.babies/activeBabyId/baby` + `setActiveBaby()` + localStorage `slownote_active_baby` 记忆
- 业务云函数普遍按 `baby_id` 过滤（feeding/growth/diary/expense/custom/milestone/statistics/checkin/aiChat/aiTasks）
- `context.scope` 用 family_id → 宝宝是家庭共享的
- 已有 baby 隔离测试：home-card.test.cjs 用 family-a/baby-a vs baby-b 交叉验证

问题清单：
1. P0 pages/baby/index.wxml:18 `＋ 添加宝宝` 的条件写反（`wx:if="{{!editingBabyId}}"`）。有宝宝时 refresh() 把 editingBabyId 设为 activeBabyId（index.js:35），按钮永远不显示 → 没有入口加二胎。截图里两个「添加宝宝」是 babies 为空时的首次状态。
2. P0 switchBaby（index.js:46）只调 app.setActiveBaby，没有 this.refresh()；baby 页也没实现 onSessionChange → 点宝宝行后「当前」标签与表单都不变，看起来没反应。
3. P1 delete 只 remove babies 文档，不级联删记录，但文案写「将删除该宝宝的档案及其关联记录」（index.js:76）。
4. P1 写入侧不校验 baby_id 归属：feedingRecord/index.js:26 等直接把 event.baby_id 落库（registration.test.cjs:96 佐证）。
5. P1 不传 baby_id 时 scope 退化为全宝宝混合（aggregation records()）。checkin 的 addProject/deleteProject 不传 → 打卡项目全家/全宝宝共享，与页面文案不一致；monthlyReport 也不传 baby_id。
6. P2 头像 cloudPath 在新增态落到 avatars/{openid}/default/，多个新宝宝互覆盖；saveAvatar 在新增态会顺手建档案（无昵称则叫「宝宝」），可能产生空档案。
7. P2 refresh() 用 `''` 表示新增模式，但 editingId fallback 到 activeBabyId → 新增模式无法保持，任何 refresh 都跳回编辑当前宝宝。
8. P2 无 babyProfile save/delete/切换 的专门测试用例。
