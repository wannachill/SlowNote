## 记录日期支持时/分/秒（SlowNote）

**用户诉求**：六个登记页只能选日期，同一天记录都显示同一时刻、看不出变化；要求「记录日期应该支持选择到时分秒，默认当前时间，这样就可以完成历史数据的注入」，并「完善 docs 和推送 github」。

**先诊断后改的结论**
- 微信原生 `<picker mode="time">` 只到分钟，用 `mode="multiSelector"` 三列（24/60/60）实现秒级；日期仍用 `mode="date"`。
- `record_date` 保持 YYYY-MM-DD，新增独立 `record_time`=HH:mm:ss；`created_at` 仍是实际写入时间，三者互不覆盖。
- AI 明细走白名单渲染、不含原始时间戳，里程碑打卡不涉及时刻 → 均不改。
- `diaryRecord.list` 是跨日期全量列表，按一天内时刻排序会打乱跨天顺序 → 保留 `created_at desc`，端侧分组用时刻展示。

**实现**
- 新增 `miniprogram/utils/record-time.js`：`TIME_COLUMNS`、`validTime`、`timeKey`（北京时间换算，空值返回空串不虚构时间）、`nowTime`、`timeToIndexes`/`indexesToTime`、`displayTime`、`recordTimeData`、`withRecordTime()` 页面包装器（注入默认值/选择器事件/回填重置；改时刻清空 `_requestId`/`_id`，避免同一 clientRequestId 被 createOnce 判重复而忽略新值）。
- `cloudfunctions/_shared/runtime.js` 新增 `validTime/timeKey/normalizeRecordTime/recordTimeOf/recordTimeValue`；`normalizeRecordTime` 缺省取当前北京时间、非法返回 `400 INVALID_TIME`。运行 `node scripts/sync-cloud-runtime.js` 同步到 14 个 `lib/`，逐文件 hash 一致。
- 四个记录云函数（`feedingRecord`/`growthRecord`/`diaryRecord`/`customRecord`）add/update 写 `record_time`；`feedingRecord.listToday/listDate` 与 `customRecord.list` 同日按 `recordTimeValue` 降序、再按 `created_at` 兜底；`statistics.daily.times` 用完整 HH:mm:ss 取当天最新、展示截断为 HH:mm（首页 rail 宽度有限）。
- 六个页面（feeding/solid/excretion/growth/diary/custom-record）WXML 改 `.datetime-row`（date + multiSelector），JS 接 `withRecordTime`、`displayTime`、`resetRecordTime`；`growth` 用 `_timeTouched` 防止 onShow/日期重查覆盖用户手动时刻。
- `app.wxss` 的 `--timeline-width` 调为 `152rpx` 容纳 HH:mm:ss；`custom-record/index.wxss` 加 `.custom-entry-head` / `.custom-entry-time`。
- 新增 `tests/record-time.test.cjs` 8 例；跨 VM realm 数组断言统一用 `Array.from`。

## 2026-11-20 追加：记录时刻精度由 HH:mm:ss 降为 HH:mm + 两个选择器等宽

**需求**：用户反馈不用登记秒，只需到时分的精度；日期与时刻选择器宽度相同。

**改动**
- `miniprogram/utils/record-time.js`：`TIME_COLUMNS` 由 24/60/60 改为 24/60；`validTime()` 严格校验 HH:mm；新增 `minuteOf()` 兼容读取旧 HH:mm:ss 并截断到分钟；`timeKey()` 改 `slice(11,16)`；`nowTime()` 默认 00:00；`timeToIndexes()` 返回两列；`displayTime()` / `recordTimeData()` / `withRecordTime.onLoad()` 统一走 `minuteOf`。
- `cloudfunctions/_shared/runtime.js`：同口径改造并导出 `minuteOf()`；`normalizeRecordTime()` 接受 HH:mm、旧客户端带秒值截断、非法仍 400 INVALID_TIME；`recordTimeOf()` 兼容旧值；`recordTimeValue()` 返回当日分钟数。跑 `sync-cloud-runtime.js` 同步 14 份 `lib/`。
- `cloudfunctions/statistics/index.js`：`times` 直接按 HH:mm 取最新与展示，去掉 `slice(0,5)`。
- `miniprogram/app.wxss`：`.datetime-date` 与 `.datetime-time` 同为 `flex: 1 1 0%`（原日期为 1.3 偏宽）；`--timeline-width` 由 152rpx 调回 112rpx。
- `tests/record-time.test.cjs`：8 例断言全改 HH:mm / 两列，新增旧带秒值截断、两个选择器等宽与 112rpx 护栏。
- docs 9 份同步：`database-design.md`(1.10)、`prd`(1.22)、`rules/frontend-standard.md`、`rules/backend-standard.md`、`rules/project-structure.md`、`rules/introduction.md`(1.10)、`deployment-checklist.md`、`release-checklist.md`、`CLAUDE.md`(1.6)；明确旧带秒值的读取兼容口径。

**验证**：`node --test tests/*.test.cjs` → 420/420；静态检查仍为原有 5 条 hardcoded visual value 告警、无新增；14 份 `lib/runtime.js` 与 `_shared` 一致。
